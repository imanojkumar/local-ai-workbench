V1.2 BOUNDARIES

Limitations

What the current release deliberately does not claim to be.

Current boundaries

01

Local / single-user

No multi-user accounts, authentication or tenant isolation.

02

Browser persistence

No authoritative server-side conversation database yet.

03

No RAG yet

No ingestion, chunking, vector store or citation pipeline.

04

No agent framework yet

No general tool registry, autonomous loop or multi-agent orchestration.

05

Catalogue is best-effort

Public Ollama page structure can change independently of the local API.

06

Hardware varies

Model disk size is not equivalent to RAM or VRAM requirements.

Security

Do not expose the development server directly to the internet.

A public deployment would require authentication, TLS/reverse proxy configuration, validation, rate limiting, logging and security review.

Model output

Local models can hallucinate, generate insecure code or misunderstand instructions. Validate important outputs independently.

Browser-local conversation history

Multiple chats, pins and project grouping are stored in the current browser. V1.2 does not provide a multi-user database, synchronization across devices/browsers, or cloud backup. Clearing site data can remove local history.

Local inference latency

Response speed depends on model size and hardware. Long time-to-first-token can occur during cold model loads. V1.2 timing is client-observed and does not yet expose Ollama's exact internal load/evaluation telemetry.

Roadmap ≠ delivered functionality

RAG, agents, tools, evaluation, alternative providers and fine-tuning are future directions. They should not be represented as V1.2 features.
