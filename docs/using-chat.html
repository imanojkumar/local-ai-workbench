Using Chat

Run local inference with a selected Ollama model and streamed responses.

Before you begin

Confirm Ollama is running, at least one model is installed, and the Workbench shows Ollama connected.

The chat workflow

  1. 01
    Select a model

    The selector is populated from models installed in your local Ollama runtime.

  2. 02
    Configure generation

    Optionally set a system prompt and temperature.

  3. 03
    Send a prompt

    Your request travels through FastAPI to the Ollama service layer.

  4. 04
    Stream the response

    Tokens appear progressively rather than waiting for the entire response.

System prompt

A system prompt provides high-level behavior guidance to the selected model.

You are an LLM engineering tutor.
Explain concepts clearly and use concise examples.
Instruction, not enforcement

Model compliance varies. A system prompt is not a security boundary.

Conversation history & projects

V1.2 stores multiple conversations in browser-local storage and organizes them in the sidebar as Pinned, Projects, and Recent. Chats can be renamed, pinned or unpinned, moved between projects, or deleted. Projects can be created, renamed, collapsed, and deleted without deleting their chats.

Browser-local workspace

There is still no server-side conversation database or cross-device synchronization. Clearing browser site data can remove the saved workspace.

Cold starts and timing

The first request to a large local model can take noticeably longer while Ollama loads weights into RAM and/or GPU VRAM. The composer reports Preparing model, Processing prompt, Generating response, client-observed time to first token (TTFT), and total elapsed time. Warm follow-up prompts are often faster.
